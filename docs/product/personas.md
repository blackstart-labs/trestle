# Personas

Status: planning hypotheses, not validated user research. Validate with real
users during the first authorized project/task pilot.

| Persona | Job to accomplish | Friction to avoid | Evidence of useful outcome |
| --- | --- | --- | --- |
| Independent developer | Plan tasks, record work, retain implementation notes | Several services, repeated entry, excessive setup | Complete a task with linked time and notes without copying identifiers |
| Small-team maintainer | Prioritize a project and coordinate changes | Inconsistent status meaning, stale boards, missing permissions | Members see consistent tasks and conflicts are explained |
| Consultant/team lead | Reconcile billable work and project estimates | Lost timers, DST errors, opaque rounding | Report totals reconcile with authorized underlying entries |
| Contributor using a phone | Find/update a task and operate a timer | Drag-only controls, overflowing tables, tiny targets | Finish the same core workflows using touch and narrow screens |
| Self-hosting operator | Deploy, upgrade and recover the installation | Hidden services, secrets in logs, unverifiable backups | Follow a documented install/upgrade/restore drill successfully |

Do not optimize solely for the administrator's desktop experience. Operator,
workspace owner, project manager and ordinary contributor are distinct
responsibilities, even when one person performs several of them.
